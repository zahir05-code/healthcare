## 🧩 코드 스타일
1. 모든 코드 작성 시 **일관된 들여쓰기**(스페이스 2~4칸)를 사용합니다.
2. 변수/함수 이름은 **lowerCamelCase** 또는 **snake_case**로 일관되게 작성합니다.
3. 주석은 **한국어**로 작성하며, 필요한 경우 기술 용어는 괄호로 병기합니다 (예: 변수(variable)).
4. 코드 변경 시 의미 있는 커밋 메시지 작성.

## 📏 동작 및 제한 규칙
1. **TypeScript strict 모드 항상 사용**  
   - `tsconfig.json`에서 `"strict": true` 설정을 강제합니다.

2. **비밀 정보 절대 커밋 금지**  
   - API 키, DB 비밀번호 등의 민감 정보는 절대 버전 관리 시스템에 포함하지 않습니다.

3. **기능 변경 시 테스트 케이스 추가**  
   - 새로운 기능 또는 수정이 있을 경우, 해당 동작을 검증하는 테스트 코드를 반드시 추가합니다.

4. **의존성 추가 시 영향 범위 분석 작성**  
   - 라이브러리 또는 패키지 설치 전, 영향 범위 및 필요 이유를 코드 주석 또는 PR 설명에 명시합니다.
## 🤖 에이전트 행동 제약
1. **Always On**  
   - 이 규칙은 항상 활성화됩니다 (항상 적용).

2. **Model Decision**  
   - 자연어로 설명된 규칙은 모델 자체 판단에 따라 적용 여부가 결정됩니다.

3. **Manual 규칙 활성화**  
   - 필요 시 `@RuleName`을 통해 특정 규칙을 수동으로 활성화할 수 있습니다.

4. **Glob 패턴 기반 규칙 적용**  
   - 파일 확장자 패턴(예: `.ts`, `src/**/*.ts`)별로 규칙 적용을 지정할 수 있습니다.

## 🗣 언어 및 커뮤니케이션
1. **출력/응답은 한국어로만 작성**  
2. 기술 설명 시 한국어 설명 + 필수 용어는 영어 병기
3. 코드 예제는 실행 가능한 최신 문법 기준

## 🔁 워크플로우 호출
1. 반복 작업이 필요한 경우 워크플로우 파일 생성.
2. 슬래시 명령(`/deploy`, `/test`)로 워크플로우를 호출합니다.
3. 워크플로우는 Markdown으로 작성되며 단계별 설명 포함.
```markdown
# Antigravity Rules (초급 개발자용)

> 파일명: RULES.md  
> 적용 대상: Antigravity 에이전트 / 초급 개발자  
> 목적: 일관된 개발 습관 형성 및 오류 최소화

---

## 1. 기본 원칙

- 모든 출력과 설명은 **한국어**로 작성한다.
- 코드는 **가독성, 단순성, 명확성**을 최우선으로 한다.
- 한 번에 하나의 문제만 해결한다.
- 추측으로 구현하지 않고, 주어진 정보 안에서만 동작한다.

---

## 2. 코드 작성 규칙

### 2.1 코드 스타일

- 들여쓰기는 **스페이스 2칸 또는 4칸 중 하나로 통일**
- 변수명 / 함수명은 의미가 드러나도록 작성
  - 예: `userName`, `fetchData`, `isLoggedIn`
- 매직 넘버 사용 금지 → 상수로 선언
- 한 함수는 **하나의 역할**만 수행

### 2.2 주석 규칙

- 왜 필요한 코드인지 설명하는 주석 작성
- 초급 개발자가 이해할 수 있는 수준으로 작성
- 불필요한 주석(코드 그대로 읽는 주석)은 제거

---

## 3. TypeScript / JavaScript 규칙

- TypeScript 사용 시 `strict` 모드 기준으로 작성
- `any` 타입 사용 금지 (불가피한 경우 주석으로 이유 명시)
- 비동기 처리 시 `async / await` 우선 사용
- 에러 가능성이 있는 로직은 `try / catch`로 감싼다

---

## 4. 보안 및 설정 규칙

- API Key, 토큰, 비밀번호는 코드에 직접 작성하지 않는다
- 환경 변수는 `.env` 파일로 관리한다
- `.env` 파일은 Git에 커밋하지 않는다

---

## 5. 파일 및 폴더 구조 규칙

- 역할별 폴더 분리
  - `components/` : UI 컴포넌트
  - `pages/` : 화면 단위
  - `api/` : 서버 통신
  - `utils/` : 공통 함수
- 파일명은 소문자 기준으로 통일

---

## 6. 에이전트 행동 규칙 (Antigravity)

- 규칙은 **항상 활성화(Always On)** 상태로 적용한다
- 규칙을 어기는 제안은 하지 않는다
- 초급 개발자 기준에서 **가장 단순한 해결책**을 먼저 제시한다
- 복잡한 개념은 반드시 단계별로 분해해서 설명한다

---

## 7. 설명 및 응답 방식

- 설명은 다음 순서를 따른다  
  1. 한 줄 요약  
  2. 개념 설명  
  3. 예시  
  4. 주의점
- 전문 용어는 처음 등장 시 짧은 설명을 함께 제공
- 불필요한 추상적 표현 사용 금지

---

## 8. 금지 사항

- 사용자가 묻지 않은 고급 개념 선제 설명 금지
- 한 번에 여러 기술 스택을 섞어 설명하지 않는다
- “보통”, “대충”, “알아서” 같은 모호한 표현 금지

---

## 9. 최종 기준

이 Rules의 목적은  
**“초급 개발자가 혼란 없이 따라갈 수 있는 개발 기준선”을 제공하는 것**이다.

모든 판단은  
👉 *지금 막 개발을 시작한 사람에게 도움이 되는가?*  
를 기준으로 한다.
```
